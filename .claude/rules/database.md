# Database Rules

## ORM & Queries
- All DB access goes through the repository layer — never query from services directly
- Use SQLAlchemy async session (`AsyncSession`) everywhere
- Never use `session.execute(raw_sql)` for business queries — use ORM expressions
- Raw SQL is only acceptable inside Alembic migration scripts

## Repositories
- Each model gets its own repository class in `app/repositories/`
- Repository methods must be typed with return annotations
- Never return ORM model objects directly from API — always serialize through schema
- Use `selectinload` / `joinedload` explicitly — avoid N+1 queries

## Migrations
- Every schema change requires an Alembic migration — never alter tables manually
- Migration message must describe the change: `alembic revision --autogenerate -m "add_user_avatar_url"`
- Always review autogenerated migrations before applying — never apply blindly
- Migrations must be reversible: always implement `downgrade()`
- Never use `DROP COLUMN` in a migration without a deprecation step first

## Transactions
- Wrap multi-step writes in a single transaction
- Rollback explicitly on failure — do not rely on connection close
- Never commit inside a loop

## Indexes & Performance
- Add indexes for all foreign keys and frequently filtered columns
- Use `EXPLAIN ANALYZE` output to justify index additions
- Avoid `SELECT *` — always select specific columns
